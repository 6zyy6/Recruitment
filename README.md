# 拾才 TalentFlow 招聘协作 Demo

覆盖社招和校招的内部招聘工作台。使用合成数据，可执行职位确认、独立投递、CSV 预检导入、筛选、约面和评价、经理决策、Offer 答复、校招协议登记、实际入职及漏斗分析。

2026-10-20 更新：完整保留六个核心模块，补强人工门槛与证据失效规则，并接入真实模型简历复筛、Gmail 服务端核对邀请及会议入会资料。真实服务需要单独配置密钥和授权，是否已完成外部调用以验收记录为准。文本模拟面试与人工评价辅助核对仍为固定规则演示。

简历上传仍在浏览器本地解析并提取字段，候选人可通过独立页面核对。托管配置为公开访问；未启用真实服务时使用公开演示账号。配置模型密钥或启用 live 邮件后，招聘页面及 API 先验证指定的真实站点操作者，再检查 HR、经理、面试官角色。候选人仅凭邀请 token 访问本次允许范围。

## 核心模块与完成内容

| 核心模块 | 承担的业务 | 已实现的关键控制 |
| --- | --- | --- |
| 职位需求 | 社招 / 校招职位、经理用人确认、发布与暂停关闭 | 未确认不可发布；有活跃投递不可直接关闭；经理限本人岗位 |
| 候选人与独立投递 | 简历读取、CSV 预检去重、同人多岗、候选人资料核对 | 投递快照独立；核对链接限字段、限时、单次；更正不串改其他投递 |
| 甄选与测评 | 岗位条件核对、简历证据复筛、HR 复核、笔试 / 问卷 / 文本面试 | 新版甄选需要当前双报告和 HR 通过后才能进入面试、确认录用及发 Offer；测评分数不自动推进 |
| 面试协作 | 排期冲突检查、会议链接 / 会议号 / 密码、改期取消、通知登记、结构化评价 | 先独立提交再看同伴；提交锁定，退回须留原因；评价未齐不可录用 |
| 录用与入职 | 经理决定、Offer 与答复、校招协议、实际到岗 | 更正资料或重跑报告使当前旧决定失效；接受 Offer 与实际入职分别确认 |
| 招聘分析 | 同批漏斗、渠道、人数 / 投递、接受率与反馈及时率 | 基于实际阶段事件去重；零分母不伪造为零；分析使用当前角色可见数据 |

## 本地运行

Node.js 22.13 或更新版本，npm。依赖版本由 package-lock.json 锁定。

```sh
npm ci
npm run build
```

首次建立本地演示数据库时执行下面的迁移一次；不要在已有数据库上重复执行同一建表迁移。

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_flaky_fenris.sql
npm run dev
```

打开终端显示的 Local 地址，通常是 http://127.0.0.1:5173 。开发服务器与本地迁移共享 `.wrangler/state`。数据库为空时通过首次业务访问写入合成样本；本地与线上数据相互独立。

## 验证

```sh
npm test
npm run typecheck
```

针对运行中的、可丢弃的本地合成库执行集成验证。`test:api` 依次运行招聘主流程、甄选测评、候选人核对、面试邀请和公开投递五组脚本，失败会中止；依赖真实模型凭据的场景在未配置时明确跳过，不计为通过。脚本新增合成记录；面试邀请还会更改两个种子候选人的联系方式和面试资料。脚本不自动清库，仅主流程脚本显式提供 `--reset` 时才会重置样本。不要在需保留的数据上运行整套检查。

```sh
npm run test:api
```

本地模拟启用真实服务后的操作者边界时，须同时提供 `TEST_SITE_USER_ID` 和 `TEST_SITE_USER_EMAIL`，且 `BASE_URL` 只能是本机地址；模拟邮箱应与本地 `MAIL_OPERATOR_EMAIL` 一致。这只验证应用守卫，不代表托管平台身份注入已经验收。真实模型凭据通过私有环境文件传入本地 Worker，不放入脚本、源码或验收输出。默认面试脚本使用 `--mail-disabled`，不发送真实邮件。

代码交付不宣称原 Spec 全部 31 个验收场景或生产性能目标都已经通过；实际检查结果记录在 `VERIFICATION.md`。

## 技术与实现边界

- 使用 Vinext 的 Next.js 风格全栈路由、React、TypeScript 与 Cloudflare D1；SQL 建表迁移随代码交付。
- 为降低 Demo 工程规模，业务对象集合保存在 D1 的 JSON 状态中，使用全局 revision 比较后提交；会话使用独立表、随机 HttpOnly Cookie 和过期时间。具备服务端权限与并发保护，但不是 Spec 规划的完整规范化业务表。
- 初始有 8 个职位、36 名合成人员、42 次独立投递，均为演示资料。请勿录入真实招聘资料。
- 演示角色及密码见 DEMO.md，账号切换建立服务端会话。真实服务启用后另需指定 Sites 登录身份，公开 Demo Cookie 不能替代该身份；尚无企业 SSO、多租户和员工账号生命周期管理。
- CSV 文件界面限制 1 MB、1000 行；整个 Demo 状态另有约 1.9 MB 的序列化容量保护。超限拒绝写入并保留原数据，大批量招聘需要分表和异步导入。与原计划的 5 MiB 导入目标相比，此 Demo 范围更小。
- 规则核对支持学历、技能和毕业届别，未知资料需人工核实；缺失关键词不等于不具备能力。规则报告不会自动淘汰，HR 的人工结论需单独保存。
- 笔试提供固定演示题库和公开判分规则；工作偏好问卷只记录情境偏好，不是专业心理测评，不设置录用总分或阈值；文本模拟面试按公开结构词规则演示评分。答卷由 HR 在合成数据沙盒代录，未实现测评的候选人外部邀请或防作弊；简历核对邀请属于本轮新增的独立流程。
- 简历初筛采用宽进原则：整理相关线索，缺项、条件差异和未知信息不阻止 AI 复筛。完成当前岗位初筛且有正文后请求真实模型，输出岗位相关证据、缺口和追问，不生成匹配分或录用决定。报告须通过结构与逐字引文核验；未配置、失败或过期时没有模拟替代结果。新的 HR 通过要求当前真实报告；历史演示报告单独标识。文本面试及面试辅助仍为规则演示，人工分数不被改写。专业测评、录音转写和模型效果/偏差评估尚未完成。
- Gmail 核对邀请支持官方 OAuth 和服务端发送；需显式选择真实发送，只有服务返回消息 ID 才记录接受发送，不代表送达或已读。超时/不确定不自动重发。也可生成预填草稿，打开草稿不表示已发送。外部日历、短信、渠道、电子签约、背调及 HRIS 未接入；会议由 HR 在会议平台创建后录入资料。
- 资料清理仅用于合成样本演示，不代表已完成生产环境的资料期限、备份再清理、资料权利请求等完整治理。

## 简历上传与候选人核对

1. HR 在添加候选人时上传合成 PDF 文字版、DOCX 或 TXT。文件不超过 3 MiB，PDF 最多 20 页；扫描图像/OCR、加密文档和旧 DOC 不支持，界面明确说明原因。
2. 浏览器本地解析原文，以规则识别姓名、邮箱、电话、院校、专业、学历、毕业年、技能和可到岗信息。缺失或多值冲突留空待核实，不从工作年份推断毕业年，也不宣称真实 AI 识别。
3. 创建待核对档案及投递，生成默认 7 天有效的邀请。可预览 Gmail 草稿，也可在邮箱配置并授权后显式选择服务端真实发送；建档成功与发信结果分别保存，失败不必重复建档。
4. 在独立核对页核对允许字段并确认。实际更正时回填主档及本次投递，不修改同人其他投递快照；实际更正后清除本投递旧筛选结果与经理决定，原样确认则保留。两种情况均保留测评且不自动晋级，更正后由 HR 重新核对并按职责决策。

邀请使用 256 位随机 token，服务端只存哈希。重发会撤销旧链接；过期或已提交的链接不能再次修改，确认后单次锁定。核对 API 只接收允许字段，版本冲突不覆盖已有修改。

当前托管配置为公开访问，独立核对入口使用邀请 token 访问。它用于合成资料演示，真实外部送达及生产使用必须另行验收。网站自己的 OAuth 配置和发信授权不能由聊天中的 Gmail 连接替代；凭据不写源码。实际配置与外部调用结果见 `VERIFICATION.md` 及专项交接文档。

## 代码位置

`components/recruitment/` 为工作台、详情和表单；`lib/engine.ts` 为业务规则和权限投影；`lib/server.ts` 为 D1 与会话；`lib/metrics.ts` 为指标口径；`tests/` 和 `scripts/api-smoke.mjs` 为验证。

## 面试邮件邀请与答复

HR 筛选通过并保存排期后，可从候选人详情或面试日程预览并发送面试邮件。候选人通过独立链接确认参加或申请改期；发送结果与候选人答复分别显示。改期、撤销或联系邮箱更新会使旧链接失效。真实发送复用 Gmail 授权，未完成配置时明确阻止发送。详见 [使用流程、状态及验证](./docs/interview-invitations.md)。

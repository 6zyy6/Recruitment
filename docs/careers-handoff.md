# 候选人自助投递交接

日期：2026-10-20（北京时间）。本文件仅记录候选人入口的交付范围和原 checkout 验证证据；共享 `demo` 合入后的全量验证与最终发布由「完善项目核心模块」聊天统一协调。

## 本轮功能

- 新增公开 `/careers`：候选人可浏览开放职位，按关键词、社招/校招和城市筛选，查看详情后投递；企业端提供入口。
- 候选人可上传 PDF 文字版、DOCX、TXT，或粘贴简历正文。文件在浏览器提取文字，原文件不保存；文件上限 3 MiB、PDF 最多 20 页，正文上限 100,000 字符。姓名、邮箱、有效正文及明确同意为必填，缺失教育或毕业年份保持未知。
- `GET /api/careers` 只返回开放职位及候选人可见字段。`POST /api/careers` 校验允许字段、资料格式、职位状态、同意与 UUID 请求号；成功只返回参考号、职位名称和提交时间。
- 成功投递进入 HR 的 `new` 阶段，来源为“候选人自助投递”。本入口不自动推进筛选、面试或录用，不触发自动邮件；候选人核对和面试邮件沿用共享工程各自的授权流程。

## 数据与并发边界

匿名提交的联系方式未经身份验证，因此每次成功的新投递建立独立候选人主档，不关联、合并、覆盖或读取已有私有主档。相同联系方式跨岗仍保留独立主档与投递快照；同岗邮箱或电话重复返回通用冲突。

`requestId` 与规范化内容哈希用于幂等。同请求同内容返回原回执且不增加 revision；同请求更换内容拒绝。实际并发写入通过 D1 revision CAS，冲突时重新读取并校验，避免生成重复主档或投递。

幂等元数据 `careerSubmissions` 只保留于服务端存储，由 `projectState` 在所有企业角色投影中删除，不随招聘工作台快照返回。公开端也不返回候选人 ID、投递 ID、联系方式、简历或企业内部资料。

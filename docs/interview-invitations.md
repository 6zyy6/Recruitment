# 面试邮件邀请与候选人答复

2026-10-20：本次新增从 HR 排期到候选人答复的流程。邮件发送复用现有 Gmail 官方授权服务；真实发送仍取决于站点发信配置与操作者授权，代码通过测试不代表已向真实候选人发信。

## 使用流程

1. HR 完成筛选并推进到面试阶段。使用新版甄选的投递须已有当前岗位规则初筛、复筛和 HR 通过结论；旧版投递保留人工筛选依据。
2. 在候选人详情安排面试，选择面试官、轮次、北京时间和地点；线上面试填写已创建会议的链接、会议号及密码。系统检查候选人和面试官时间冲突。
3. 在候选人详情的面试记录，或「面试日程」，点击「发送面试邀请」。先预览收件人、主题与正文，再明确点击发送。
4. 邮件包含岗位、轮次、时间、地点和入会资料、准备事项，以及独立答复链接。收件人使用候选人**当前主档邮箱**，资格报告继续使用本投递快照。电话建档的候选人补充主档邮箱后即可预览新地址。
5. 候选人打开链接，无需内部演示账号，选择确认参加或申请改期。改期申请须填写 5–1000 字符原因及建议，HR 可在面试记录查看答复；申请不会自动更改时间。
6. HR 调整排期或入会资料后，旧邀请撤销，需重新发送。撤销邀请不会召回已发邮件。

## 状态与恢复

邮件状态与候选人答复分别记录：

- 邮件：发送处理中、Gmail 已接受发送、明确失败、结果未知。Gmail 接受不代表已送达、已阅读或候选人已确认。
- 答复：待答复、确认参加、申请改期。提交后锁定，调整由 HR 处理。
- 有效的处理中、已发送或结果未知邀请禁止直接重复发送。明确失败允许重新预览后手动重试；结果未知时先核实 Gmail 已发送邮件，再明确撤销旧邀请或刷新核实。
- 发送前先以 revision 比较后提交保存 pending，随后调用 Gmail。同请求标识或并发点击只会有一个获准发送。Gmail receipt 存在 mail_jobs；若 JSON 状态回写冲突，刷新可补回，同一回执不重复追加事件。

## 入口与校验

- POST `/api/interview-invitation`：HR 的预览、发送与撤销操作；真实发送还须通过现有站点邮件操作者检查。
- GET/POST `/api/interview-response`：仅凭 256 位随机 token 读取本场必要资料和提交答复。正文链接使用 URL fragment；服务端只存 SHA-256 哈希。
- 邀请最长七天有效，在面试开始时截止。撤销、排期/会议资料变化、当前主档邮箱变化、投递关闭或进入 Offer 后，旧链接失效。
- 面试邮件摘要仅提供给 HR，完整 token 集合不进入任一内部角色投影；面试官继续遵循原资料权限。匿名清理会删除邀请联系邮箱、答复和 token 记录。
- 邮箱连接沿用 `docs/variables.md` 的 Gmail 配置。未配置或未连接时，页面显示「连接招聘邮箱」入口，发送返回错误且不伪造成功。

## 验证

在 `/demo` 合并后执行 `npm test`：188/188 通过，其中本功能新增 20 项业务、9 项服务端发送编排及 4 项生命周期测试。服务端发信测试 mock Gmail 边界，没有发送真实邮件。

隔离的本地 5184 服务执行：

```sh
BASE_URL=http://127.0.0.1:5184 node scripts/interview-invitation-smoke.mjs --mail-disabled
```

9/9 场景通过，覆盖真实 HTTP 的预览无写入、有效收件邮箱、补邮箱、角色权限、并发版本、无效 token、跨域写入拒绝，以及未配置发信不生成成功记录。脚本只允许本地合成测试数据；`--mail-disabled` 另要求服务端 mailReady=false，不向真实邮箱发信。

另在隔离 D1 注入合成 pending 邀请，浏览器验证候选人独立答复与 HR 可见结果。真实外部邮箱的送达验证须在 Gmail 配置完成后单独执行；本次不以 mock 或 pending fixture 宣称真实送达。

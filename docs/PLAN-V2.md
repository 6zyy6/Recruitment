## 交付范围

| 核心模块 | 本轮可操作能力 | 边界 |
| --- | --- | --- |
| A 分层甄选 | HR 配置最低学历、必需技能及适用届别；逐项核对条件；生成带资料证据的复筛报告；HR 保存结论与依据 | 缺失为待核实，规则不自动淘汰；复筛为固定规则演示，未接入真实 AI |
| B 测评评估 | 可选客观笔试及自动判分；工作偏好问卷与维度报告；文本面试问答及规则评分；人工独立评价后核对本人评分及证据 | 问卷非已验证性格量表，无录用阈值；文本与辅助评分是规则演示，经理最终决定 |
| 日程视觉修复 | 重新设计月份、日期及星期层级，统一尺寸、留白和行对齐 | 不改变已有安排、改期、通知和评价规则 |

默认路径为：岗位标准确认 → 条件初筛 → 简历证据复筛 → HR 复核 → 可选问卷/笔试 → 可选文本面试 → 人工结构化面试 → 独立提交后辅助评分 → 人工决定 → Offer → 实际入职。按岗位选用环节，不要求所有候选人完成全部关卡。

| V211 | 保存规则、结论、作答与报告后刷新/重登；尝试高分跳过人工门槛 | 数据仍按权限可读；冲突失败不显示成功；无分数自动推进、淘汰或录用，原经理与 Offer 门槛保留 |

自动化验证规则、权限和保存，浏览器验证可操作性与视觉。验证记录须说明实际通过及未执行项，服务重启、备份、容量和真实 AI 评测不能由一次刷新替代。

## 执行与交接

1. 同步主计划与需求、技术、验收子文档，检查新增能力与原范围无冲突。
2. 实现规则、证据及 HR 复核，验证配置校验、未知信息和人工决定。
3. 实现测评作答、确定性评分及独立人工评价后的辅助报告，验证证据与权限。
4. 修复日期卡并走查三个桌面宽度，回归受影响的已有流程。
5. 交付更新入口、源码、测试/浏览器记录、演示路径与明确限制。

V201–V212 为原 V2 发布门槛，本轮追加 V213–V220；原 AC01–AC26、NF01–NF03 保留为完整产品合同，未执行不自动通过。真实 AI、岗位适用性已验证的性格工具、外部考试、语音转写、监考、公开对外的完整候选人门户与渠道/消息集成另行规划。全链路仍覆盖需求、渠道、投递、甄选、录用、入职、人才经营、分析与资料治理，不因本轮选择两个模块而删去。

## 2026-10-20 追加 简历上传与候选人核对

新增 R22 简历上传识别、R23 候选人自助确认、R24 Gmail 草稿邀请。HR 上传简历，在浏览器本地解析后按规则提取姓名、邮箱、电话、院校、专业、学历、毕业年、技能、可到岗信息及原文，先创建待核对档案及投递，再让候选人修改确认。缺失或多值冲突留空待核实，不把工作年份推断为毕业年；规则提取不冒称真实 AI。

支持 PDF 文字版、DOCX、TXT，最多 3 MiB，PDF 最多 20 页。扫描图像/OCR、加密文档和旧 DOC 不支持，需明确报错。默认邀请有效期 7 天，使用 256 位随机 token 且服务端只存哈希；单次提交锁定，重发撤销旧链接，接口限定可写字段并检查版本冲突。

候选人实际更正仅回填主档和关联本次投递，不改其他投递快照；实际更正后清除本投递旧筛选结果与经理决定，原样确认保留已有结果。两种情况均保留测评且不自动晋级，更正后需 HR 重新核对及按职责决策。当前邮件路径是在 Gmail 打开预填草稿，由用户最后点击发送；不把打开草稿标记为已真实发送，不在源码保存私人邮箱。

当前托管配置为公开访问，独立核对页使用邀请 token 访问。交付范围为合成资料的可操作核对流程；网站自动真实发信及真实外部候选人的送达、生产使用仍待接入或验收，不能据内部验证宣称真实外部邀请全链路已通。

## 核心模块质量补强

六个核心模块为职位需求、候选人与独立投递、甄选测评、面试协作、录用入职、招聘分析。项目基础还须包含权限、审计、保存与并发控制、请求校验、配置说明和可重复验证的交付记录；对应代码与测试见 `docs/architecture.md` 和 `docs/tests.md`。

本轮成功标准：新增用例先复现已发现的核心规则缺陷，修复后全量单元测试与类型检查通过；新版甄选的当前 HR 通过结论贯穿进入面试、经理录用与发 Offer，更正资料或重跑报告后不得复用旧决定；HTTP 验证涵盖主流程、甄选测评及资料核对；站内能看清每个模块做了什么，工程交接说明实际边界。
